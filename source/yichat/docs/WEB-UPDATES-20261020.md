## 实现

1. 主页账户菜单加入「YIDT 钱包」，不依赖已有会话。读取真实绑定状态，沿用 YIDT `/services/yichat/` 的选择钱包、支付密码/锁和 CSRF 表单。使用当前标签页前往，确认后返回聊天；绑定不扣款。会话中的绑定入口保持相同逻辑。
2. 会话列表、消息日期/时间、订单截止、交易与赠卡时间使用浏览器系统时区；传输时间戳及归档日依旧 UTC。不是改写消息正文中的任意日期字符串。
3. Synapse 模块对实际撤回目标读取原接受时间，5分钟外拒绝；普通原生 token 同样受约束。业务消息最小引用在密文外层，验证真实记录与会话后保护，转账/红包/赠卡不可撤回；群内真实订单链接也受保护。撤回不改写旧封存包或金融/资产账本。
4. 增加原事件包的认证增量更新和在线成员转交。复用原统一存证 SHA-256，不做自创加密；本地恢复只向时间线添加历史事件，不再次发送消息。每个房间保留更新位置，常规回看5分钟，重新进入回看10分钟。游标在待补齐状态持久化后推进。
5. 赠卡在原资产事务中同时保存原渲染器所需的卡面快照，消息内双方自动显示；旧赠卡只在原权限仍能读取时显示真实卡面，无数据明确降级。卡片再转送不改变原赠送快照，预览没有资产写操作。
6. 主页、会话列表、消息、查找结果及成员详情使用主站头像；详情显示主站简介。新增批量 username 资料查询，未 provision Matrix 的用户也可查询；不通过用户名推断/重建既有 MXID。头像请求合并、同一版本缓存，并在退出释放 Blob URL。

## 历史补齐的边界

- 永久保留的是原始包 SHA-256、事件标识、接受时间、顺序与撤回/业务引用等小元数据。正文仍按既有存证/30日清理规则，不建立另一个永久正文库。旧封存文件内容/摘要不改变。
- 服务器仍有的包直接提供。短暂缺失、存证回填未完成、依赖故障返回503，不对外索取。只有明确超过保留期、已经完成清理且保留可信摘要的缺包才形成成员请求。
- 在线成员必须当前属于房间，且原事件发生时有历史权限。发送的是本地缓存的原canonical字节；服务器先核对可信哈希、事件ID和room，再转交；接收端再做同样核验并使用原Matrix SDK解密。
- 私聊和旧加密群转交只允许 `m.room.encrypted`。不提交解密正文、附件解密密钥、恢复密钥或设备私钥。撤回控制由服务端认证元数据提供，不要求成员上传私聊明文控制包。
- 成员转交使用同源认证 HTTP 临时缓冲，TTL120秒、256请求、总数据8MiB，每个活动客户端20秒合并调度；不是浏览器裸连接/WebRTC，也没有重新发送历史到房间。沿用共享请求限流和429退避。
- 本地事件包加密缓存最多100MiB/10000条。没有在线且持有副本的有权成员时，显示待补齐。部署此机制前已经彻底清理且未留下单包摘要的历史不能凭他人自报哈希冒充可信数据；已过期附件实体不在这条事件包协议中恢复。
- 已看过原消息的成员即使在撤回时短暂离群，重新加入后也会取得撤回标记。新成员不能借此取得原本无权的正文。

## 恢复密钥与房间说明

当前界面使用 Matrix SDK 在本设备随机生成的恢复密钥，不是让服务器保存一份聊天密码。它解锁安全存储及加密密钥备份，进而恢复会话解密密钥；聊天消息实际使用 SDK 自动生成/轮换的 Olm/Megolm 密钥。丢失全部旧设备及恢复手段时，只有密文包和登录密码也无法解密。

Matrix 标准允许以用户自设恢复口令经标准派生保护密钥；本界面尚未提供自设口令入口。已有恢复密钥不会因本轮更新被重置、上传明文或更换。

「房间」是Matrix会话模型，私聊也有一个只有双方的房间。目前使用邀请加入和 joined 历史权限。加入是获取会话及设备密钥分发资格的一部分；加入后不需要双方同时在线。端到端加密的数学性质不要求用户手动点「加入」，手动接受是当前产品与权限策略，不是所有加密聊天都必须采用的交互。

依据：[Matrix Secret Storage](https://spec.matrix.org/latest/client-server-api/#secret-storage)、[Matrix E2EE Guide](https://matrix.org/docs/matrix-concepts/end-to-end-encryption/)。
