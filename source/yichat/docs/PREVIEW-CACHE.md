# 独立内容布局与预览缓存（0.3.7）

## 显示

站内分享、赠卡、图片、音频、视频和文件使用 `content-bubble` 类：外层无背景、边框、内边距或阴影；保留中间预览自己的边框和外观。普通文字、选择取消预览的原 URL、撤回和失败解密提示保留原气泡。发送方/接收方、私聊/群聊、发送中/失败草稿一致；带预览的说明文字保留，预览原 URL 继续隐藏，时间、回复、已读和消息操作保留。

## 存储与隔离

`PreviewCache` 不依赖 UI 框架，通过可选存储适配器读写。Web 使用内存缓存；App 使用现有本地 Vault（IndexedDB v3）新增的 previews store，不进入公开静态 WebShellCache 或消息原包。Vault 升级仅增加 store，不删除现有消息、草稿或密钥。

Vault 本身以账号 UID、MXID、设备 ID 和现有 message epoch 隔离。预览键包含 UID、设备 ID、room 和 URL/赠卡标识；落盘键为 SHA-256，预览数据和期限通过已有 WebCrypto AES-GCM 加密，以哈希键作为 additionalData 绑定。沿用现有非导出包装键，不另造密码学实现。

每项独立落盘，缓存最多 160 项和 24 MiB；写入时删除过期项并按最早写入顺序淘汰。每次命中不重新写整个缓存。退出时内存缓存关闭，正在返回的请求不得更新新会话；本地库沿用现有锁定语义，其他账号或设备不能读取。

## 时效

| 内容 | 有效期 | 行为 |
| --- | --- | --- |
| 交易哈希记录、跳伞固定结果、斗地主对局记录 | 30 天 | 有效期内打开或离线重开直接读取本地 |
| 公开卡片 | 60 秒 | 有效期内复用；可见时每 20 秒检查缓存，过期再联网核实 |
| 斗地主房间邀请、赠卡 | 20 秒 | 短期复用；可见赠卡保留原状态轮询 |
| 订单初始预览 | 5 秒 | 操作及 OrderBubble 状态继续读取权威订单接口 |
| 无效/销毁资源返回 null | 20 秒 | 覆盖旧卡面，避免重新恢复旧内容 |

缓存减少重复预览请求，不能将可变状态永久冻结。短期预览过期后不从磁盘恢复旧值；离线打开过期卡片可能需要联网核实。固定结果在缓存有效期内可离线读取。卡片转手不改变 URL，销毁后服务器的无效结果覆盖缓存；明确 401/403/404/410 清除旧缓存。未收到服务器更新前，最多受上述短期有效期影响。

刷新卡片状态、刷新房间/记录等按钮绕过缓存强制请求。同一资源并发加载合并；强制刷新排在既有请求之后，避免旧回执覆盖新结果。缓存损坏、满额或写入失败不阻止正常在线预览。原消息始终只保存 URL/正文，卡面仅在本地展示缓存。

## 验证与手机检查

单元测试覆盖跨实例持久读取、键隔离、并发合并、强制刷新、卡片失效、访问撤销、损坏存储、锁定时的在途请求、容量淘汰与各类 TTL。浏览器使用真实 IndexedDB、WebCrypto 和 App 桥适配：加载卡片/游戏预览后关闭页面，再以离线 App 状态新开页面，确认无新的 /api/preview 请求；验证密文落盘及手动刷新失效。

手机 Chrome 刷新后检查图片、文件、站内卡片与普通文字；App 覆盖安装后打开包含 URL 的会话，返回列表再进入、划掉最近任务后重开，观察缓存直接展示。卡片状态可手动刷新；固定记录应在有效期内离线可读。检查浅色/深色、双方消息、说明文字、回复和时间。真机行为仍应在用户手机完成回归。
